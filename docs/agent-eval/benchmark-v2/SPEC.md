## 非视频专项守卫

冻结时显式传 `--nonvideo-guard --cases B04,B41,B42,B44,B46,B48,B49,B50` 或其非空子集；选择 B47、其他题、重复或未显式选择均拒绝。manifest 的 `model_configuration.benchmark_guard` 固定策略版本及题目，运行器和每题宿主核对；不得在运行时切换策略。守卫拒绝视频生产入口，并以拒绝所有平台操作的客户端替换真实发布适配器；宿主确认接线后记录 `guard.json`。默认未启用模式保持原样。B47 不属于此实验，拒绝不记作该题通过。

DeepSeek、Codex 图片 SDK 和联网调研仍是真实调用，ffmpeg/ffprobe 保留用于素材种子；此守卫不是进程或网络沙箱，不能保证约束外部模型、子进程或第三方服务的任意行为。受限批次与无此守卫的旧基线执行环境不同，不能视为相同条件的前后对比；守卫本身不证明题目成功。manifest 是本地留存记录而非防篡改签名，归档与比较时须核对其内容及冻结源码。

守卫批次的单题报告、summary 与 RESULTS 明示冻结策略及可比性限制；单题完成前和批次汇总时核对 `guard.json` 的完整策略、题目和接线标志。缺失或不匹配时该题不能判成功，保留已有原始报告及实际采证；历史无守卫批次保持原有读取规则。

## 逐题定义

- intent：用户实际要什么；expected_outcome：理应得到什么；evaluation_scope：最终结果、必要轨迹或多轮链路。
- scoring.program_checks：本题实际计入程序分的检查ID、中文说明和关键标记；rubric：本题语义二分类问题。规则数量按任务需要，不统一凑数。
- 简单CRUD检查最终正确对象、内容、状态及用户禁止的副作用；不要求先查再写或唯一工具顺序。多轮、并行、后台续接和交付修复才检查必要依赖。
- 权限/泄露/禁止动作和原前端完成、刷新、Trace读取完整性是共同关键门禁；浏览器错误不扣业务分，但不能整题通过。明确禁止的重复生图等关键项失败不能由其他项抵消。宿主强制探针与模型自主操作分开解释。
- 格式、Schema、一般调用预算、冗余候选、Token/缓存/时延/成本保留诊断，不自动当业务失败。题设明确要求的零工具、不得重复查询等仍是任务条件。

## 计分

- 程序分与语义分分别为100×通过项数/本题适用项数。任一项缺证据，该维度完整分数为null，另报已观测分数、覆盖率和逐项原因；不默认0或100。
- Judge须为每条冻结语义规则返回唯一id、true/false/null和证据；重复、缺项、错误类型或调用失败均不是通过。
- 集合分别对每题程序分和语义分取均值，不按全体规则数加权。计划题缺分时完整均分为null，单列已测均分及题目覆盖率。
- 不设置两类分数权重，不产出综合加权分。严格通过仍要求两类全部满足、关键门禁通过且真实执行完成。
- 当前Judge未与人工标注校准，不声称评分等同用户判断。现有少量图像输入不代表完整视频/听音或作品审美评测能力。

## 执行与证据

- 冻结题目/判分器/产品源码/配置后，从真实前端执行；每题独立进程、磁盘SQLite、会话与文件根。外部真实API费用和SDK全局状态不能事务回滚。
- 付费Live显式运行；本轮仅定义标准和测试评分/读取/前端，不重跑50题或重启正式服务。
- 记录真实SQL前后、工具参数/回执、浏览器刷新与媒体读取、Codex事件、Judge逐项结果和用量；缺证据保持待复核。
- 同批同题首尝试只一次，不择优；新规则新建批次，旧数据、分数、失败和图片不修改、不自动重跑。
