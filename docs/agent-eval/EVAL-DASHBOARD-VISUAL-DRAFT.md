# Eval 看板视觉布局草案

状态：待讨论的低保真设计；示例数据均为虚构，不代表实际结果。仅设计，未实现。

## 设计方向：轮次工作台

一眼看到「这次改了什么、与谁相比、哪些问题阻止结论」。以文字和对齐的行构成界面，不用大 KPI 卡片、趋势图或装饰插图。背景近白、正文炭黑、细灰分隔线；唯一操作强调色为深蓝。状态使用文字加图形：失败红色实心圆、待复核琥珀空心圆、未运行灰色短横、运行中蓝色动态点、通过绿色对勾；不依赖颜色。单一无衬线字体，标题 22 / 分区 16 / 正文 14 / 辅助 12px，数字等宽。状态优先于装饰，横向对齐让不同轮次和结果易扫读。

左栏约 280px 固定宽，右栏自适应、内容最大宽约 960px；选中轮次有左侧蓝线及浅底。左栏只放正式评测轮次，未合并正式记录也可见；临时测试在轮次详情的运行记录中标记。状态汇总不以单一分数替代，安全失败突出且不能被通过数抵消。专项各自默认该专项最新运行，选择器可回看同版本先前运行；不会跨专项复用最近运行。基础测试收起，但失败时展开并置于待关注区。

比较区始终给出双方、共同可比题数及分母；差异详情显示题集、评分、模型、环境和执行条件。不可比时显示「不可直接比较」及原因，隐藏涨跌；模型为被测改动时允许呈现对照但说明模型已变化。Token/耗时独立展示来源、计量范围和未知值，不把样本不足描述为稳定改善。基准无法确定时显示「选择基准」，不按时间猜测。

## 测试集与单题

点击专项进入题目列表；顶部保留面包屑「轮次 / 工具调用」和本次运行选择。列表按失败、待复核、未运行、通过筛选，行展示题目、状态、本轮结果、对比状态和证据；失败与证据不足各有原因。默认不靠分数排序。

单题进入独立详情页，首屏依次为用户任务、结果与状态、基准变化、判断依据；明确失败与缺证的不同原因。下方折叠「工具调用」「输入与返回」「原始证据」并标真实模型 / 替身、证据缺失原因。返回保留题目筛选和滚动位置；技术长文本换行或局部滚动。

## 版本与回溯

「版本详情」进入独立页面，显示代码和配置快照、提示词、工具定义、模型参数、依赖、题集与评分版本，密钥不展示；未提交内容需有可恢复快照。明确区分轮次、版本与运行，保留每次运行和历史证据；无法关联轮次的旧批次在历史记录只读展示，不重算。比较选择器可搜索历史版本并查看可比性。

「回滚」仅作为未来能力示意；在恢复条件未经验证前显示不可用及原因。未来可用时先展示目标和检查结果，明确暂停新任务、等待运行任务、数据兼容与验证；阻塞原因可见，不暗示任务自动取消或重发。

## 状态与交互规则

- 加载用对应区域骨架；无轮次说明正式记录尚未登记，旧数据入口仍可见；筛选无结果提供清除筛选。
- 运行中显示进展和已知结果，不提前给整体结论；失败、终止、结果未知分别显示，保留运行记录。
- 必要测试未运行显示原因并标「未验证」；证据不足标「待复核」，专项和完整链路未完成不显示整体通过。
- 网络错误保留已选轮次和基准，提供重试读取；刷新后从 URL 恢复轮次、基准、运行及筛选，避免重新提交测试。
- 所有状态使用文字加形状，键盘可操作、焦点可见，长标题与长理由可换行；图标不作为唯一含义。

## 待确认

此方案以列表与结果同屏为主，首要决策是用户是否希望轮次切换留在左栏。比较分母、状态与版本信息具体字段仍须对照实际数据契约；这里的所有能力均为目标，不代表现有系统已实现。视觉与交互需将来分别在桌面、手机以及加载、空、失败、长内容状态验收。
