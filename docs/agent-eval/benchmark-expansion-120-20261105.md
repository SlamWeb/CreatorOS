# CreatorOS Agent Benchmark 扩充至约 120 个任务实例

状态：2026-11-05，**研究与候选规划，不是已实现题集、运行成绩或用户验收**。本文件不授权批量创建生产、真实发布、重试历史任务或改写历史成绩。现行定义仍以 [受控回归 SPEC](benchmark-v2/SPEC.md) 和 [自然表达题集](natural-v1/README.md) 为准。

补充：自然题的评分已另建 [v2](natural-v2/README.md)，其20个请求与 v1 配对相同，不额外增加任务实例。下表“实际请求实例”的 70 不因版本升级变成 90。

## 计数口径

| 口径 | 当前事实 | 解释 |
| --- | --- | --- |
| 受控业务任务 | 50 个 B01–B50，题集 `creatoros-trace-benchmark-v3.4-20261105` | JSON 元数据有 45 个 `family`；家族只是当前标注，不能直接视为 45 项独立能力。 |
| 自然请求变体 | 20 个可显式选择的合成改写 | 均与上面某个任务配对；自然集其余 30 行是兼容宿主占位，**不是题，也不能执行**。可称 20 个请求变体，不能算 20 种新业务能力。 |
| 实际请求实例 | 两套各按自身版本冻结的 50 + 20 = 70 个定义 | 仅是不同任务请求实例，不表示已在同一版本全部执行或具有 70 个独立家族。 |
| 真实执行 | 旧 v2.1 基线 50 题；自然集另有 3 个首尝试 | 旧规则及旧源码结果不得充当现行 v3.4 成绩；B06、B11、B16 自然题的 3 次试跑不是全部20题成绩。参见 [历史记录](benchmark-v2/ROUND-002.md) 和 [自然集运行记录](natural-v1/README.md)。 |
| Judge 校准输入 | 另有合成语义样本与可复核证据 | 它们是评判器测试，不是 Agent 任务题；规则条数、程序断言、候选图片、多次 trial 均不计入题数。Judge 尚未经人工标注一致性校准。 |

建议目标：保留现有 **50 个受控回归任务实例 + 20 个自然表达配对变体 + 新增 50 个任务实例 = 120 个任务实例**。这不是“120种能力”或“120项彼此独立的任务家族”。新增项只有在题面、场景、预期、证据、评分及可执行验证都完成后才能计为实现；若仅完成候选草案，应另报“候选”，不能算进 120。

每条请求变体如果只变换栏目名、词组、措辞或数据种子、且风险与通过标准相同，不应伪装成新增业务家族。原题与自然变体保留 `family_id`、`parent_case_id` 和 `variant_kind`，分开报告结果；只有新增独立目标、状态、约束或故障机制的题，才考虑建立新家族。下面 50 项均是需进一步核对产品契约及去重的**候选**，不是承诺每项必然成立；发现与现有题等价就合并或替换，而不是机械凑数。

## 50 项新增候选

每项列出请求目标、新风险、最低可判证据。对要求目标是否应自动执行、确认或澄清而当前契约未定义的案例，先查产品契约；仍有业务分歧时集中确定，不预先编造标准。

## 分组、判分和可比性

1. 为每条记录 `case_id`、`family_id`、`parent_case_id`、来源（真实脱敏 / 合成 / 故障注入）、受控夹具与数据版本、用户请求、授权边界、预期结果、必要因果约束、关键门禁、评分证据与失败/未知的区别。多轮仍是一道任务；每次执行单独记录 trial ID。强制权限探针与模型自主行为分别记，不将探针成功冒充模型主动通过。
2. 先按风险家族和来源聚类再划分开发与验收；对应原题和自然变体、同一 Trace 改写、同一答案线索/共享夹具的近似题不得跨组。现有 50 题为 40 dev / 10 acceptance，自然 20 为 19 dev / 1 acceptance；现有 acceptance 内容公开，不是盲测。新 50 可以暂按约 31 开发、19 验收规划，再根据家族完整性调整，不把配额置于防泄漏之上。真正未知留出需独立访问控制、冻结后不得参与调参及泄漏检查；若题面或答案已公开，应称公开验收集。
3. 确定性结果优先用对象 ID、SQL、哈希、权限回执和真实媒体元数据核实；语义/视觉由 Judge 按原子规则判断，缺少证据记未知。逐项设计正确、错误和缺证据反例，独立展示可复现数据、Judge 原答与资格判断。AI 自标或多模型一致性不是人工真值；需要人类一致性结论时再做小规模、独立的人审校准，而非默认为100%。
4. 单次首尝试用于定位当次问题，关键高风险任务可在独立世界重复 trial 衡量波动；报告分母、缺测、模型/配置/版本与离散结果。不要以多次重复或失败重试充当更多任务，不对没有独立多 trial 的数据计算稳定性或 pass^k。
5. 文本、低风险状态和程序回归可高频跑；真实图片、视频和外部调研分开预算与输出路径。先用同版本少量不同类别的真实 pilot 测调用数、时间和 token，再估全量成本；Codex订阅与外部副作用若不能定价就标未知。旧 v2.1 的美元估算只代表当时冻结费率及执行，不是新版本报价。付费执行显式触发，不自动重试未知结果、不启动历史任务、不发布。

## 实现入口的先决条件

- `creatoros/evaluation/benchmark/manifest.py` 当前冻结/验证要求按序完整 B01–B50；`report.py` 与 `store.py` 也校验同一集合。现行自然集通过50行兼容投影和显式资格限制运行。**直接追加 B51–B120 无法完成目标。**
- 在新增题之前设计独立的可版本化 suite schema：明确题 ID、允许执行的任务集合、family/来源与子集选择；manifest 按各数据集真实定义冻结，结果/网页按该批冻结题集读取。严格验证重复 ID、空集合、越权选择和快照哈希，历史 B01–B50 的 manifest、报告和结果只读兼容。不要以占位行填充新套件或把30个占位算作自然题。
- 针对新多模态与来源题先完善采证：图像身份和实际发送、视频帧/音轨与素材绑定、试产评分与具体作品绑定、来源实际正文/引用对应。当前无足够证据的项保留待复核，不能为让新题变绿而放宽守卫。

## 交付阶段和简历表述

1. **盘点和冻结设计：**复核这50个候选与现有题目的独立风险；梳理 family、来源、拟测行为、外部副作用、需要的可观测证据，输出明确总数与不可实现项。
2. **先贯通一小批：**每类先挑代表题完成环境、参考解、程序/语义规则及正反/缺证据测试；必要时用真实低成本调用验证连线。不是每行草案都能自动变成可执行题。
3. **分批实现到目标：**按风险与真实使用价值补全可执行实例，归档不可计数的近似题，验收题按家族隔离；每一批形成 manifest、版本、说明、独立记录和可重复测试。
4. **独立验证和交付：**在事先冻结的数据和评测代码上运行适用批次，逐项保留环境故障、产品失败、Judge 错误和未知；公开定义、实际运行条数、语义覆盖、成本与残余限制。新增题、模型运行和人工校准是三个不同的完成状态。

如果实际完成了120个可执行实例，可如实写：“设计并实现覆盖120个任务实例的 CreatorOS Agent 评测，包含受控业务任务及自然表达变体，分离程序和语义评分。”若同时声称“运行120题”或通过率，则必须有同一冻结版本的120题实际运行记录及相应分母；在此之前应写当前可核验的现状或明确标作扩充目标，不以简历数字倒推制造结论。

## 方法参考（第一手来源）

- [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)：区分任务、试次和评分器；采用受控环境、结果验证与适当的人类校准，并允许未知结果。
- [OpenAI：Separating signal from noise in coding evaluations](https://openai.com/index/separating-signal-from-noise-coding-evaluations/)：评测任务本身可能有规范、测试覆盖或判分问题；独立审查和分歧归因不可省略。
- [OpenAI：Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：根据任务目的选择数据、评分和持续评估，模型评分需有参照与校准。
- [METR：MALT](https://metr.org/blog/2025-10-14-malt-dataset-of-natural-and-prompted-behaviors/)：示例性地把任务、任务家族和轨迹数量分开，并对可公开数据及留出范围明确标注。
