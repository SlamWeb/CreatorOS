## 以后怎样得到简历能用的提升数字

1. 冻结同一组用户任务、受众、数据规模、模型配置、采集器及判据。真实 GUI 发 query，不给模型参考答案或数据库 oracle。
2. 全题首次基线结束后再改业务实现；同题、同判分器全量回归。每个槽一次 first-attempt，失败和环境错误保留，重复验证另开 batch。
3. 分开统计执行证据完整、数据库/权限正确、最终交付准确、宿主导航可用。图片生产另报实际图片与内容质量，不混入账号 Agent 的成功率。
4. 完整任务通过需证据、业务、交付三个层次均通过；缺语义复核为待评估。界面测试绿不等于模型答对。
5. 链接交付改造后，原回答原样保留，新的宿主导航成绩单列。旧“模型必须在正文写 URL”的程序检查仍作为历史协议输出；不能把宿主补出的链接算作模型原来没有编造。
6. 扩展覆盖先以 [50 场景规划](COVERAGE-V3.md) 分层接线；`planned` 不等于已运行。要写稳定性提升，优先给固定账号组补独立重复，报告分母、样本及评估者。

当前已确认的是“构建了真实前端评测、保留失败并以 Trace 和数据库断言定位问题”；尚不能写通用成功率、Token 优化或发布运营闭环。
