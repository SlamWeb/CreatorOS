# Eval Harness 与看板：设计草案

状态：讨论期间的工作草案。用户已确认的方向见 [讨论记录](EVAL-DASHBOARD-DISCUSSION.md)；以下默认方案尚未实现，也未宣称已有自动选集或回滚能力。

## 目标与范围

为开发 session 提供测试集、运行和留证能力，让用户按更新轮次理解改动、结果及其与历史版本的差异。正式评测与临时调试分开；不以题目数量、模型自述或 Judge 分数代替真实完成证据。现有 Eval 前后端可重建，但历史记录及其原始证据必须保留。

## 评测过程

1. 开发端声明改动范围、版本和目标，评测体系给出必要与建议测试；可增加临时测试或扩大正式测试范围。正式申请冻结规则版本及必要项清单。声明与实际改动冲突、范围不明、规则未覆盖或必要项未完成时标为未验证，不能把建议集当作覆盖保证。
2. 正式评测在运行前向唯一共享登记处原子登记版本、题集、选题和评测配置，确认成功后才开始正式运行；登记不可用时可本地调试，但不能声称正式运行已经登记。运行成功、失败、终止或结果未知均留记录。临时测试另行标识；不能把已失败的正式运行改成临时测试。
3. 每次运行使用独立测试世界与输出；真实模型、外部服务、替身、网络和副作用按实际标注。运行前声明能力、外部动作、凭证和费用约束，发布能力默认禁用并验证；无法确认副作用的题记为未运行。独立目录或非视频守卫不等于网络沙箱；调用失败或结果未知不能盲目重试付费动作。
4. 报告测试范围、通过、失败、未运行、待复核及理由，安全关键项单列。更新一次代码或配置对应新轮次；一轮可有同版本的多次运行，并保存全部运行。
5. 按需先专项再跨链路；常规全量回归为经核实无需重型资源且副作用受控的固定题集，完整回归额外覆盖 Codex、生图、视频等。逐题依赖和耗时、费用实测后决定归属；未运行不算通过。

## 看板与结果

- 首页左侧是轮次，右侧是改动说明、版本对比、专项与完整链路、安全边界和待关注问题；基础测试默认收起、失败时突出。主看板可看到已登记的未合并正式评测和合并状态；临时调试不自动铺满首页。
- 点击测试集进入题目列表；单题优先显示用户请求、结果、对比和判断依据，原始工具调用、参数、返回值和证据按需展开。
- 同一专项默认展示该专项最近一次运行，而不是把其他专项的最近运行覆盖它；同时显示首试、尝试次数及此前失败，不能把后续一次通过说成稳定通过。试题、判分器、夹具或驱动变更要有独立版本；不同版本不拼成同一结论。
- 默认对比同一开发线的上一轮；如无法判定前驱则要求选择，允许手选其他版本。关联关系显式保存，不能仅用时间猜测并行分支的父子关系。
- 汇总单轮范围，直接比较题目与夹具、判分与采证、驱动、执行世界/守卫和试次定义可比的共同案例，明确分母、未测和待复核；目标改动允许不同并明确列出，其他关键条件不匹配或缺失时并排展示但不计算涨跌。模型变化如果是被测改动，可展示对照但不能宣称其他条件一致或自动归因。
- Token 优先用供应商实际用量，估算另标，缺失保持未知；费用记录价格来源和计价版本，耗时明确起止范围及环境。样本过少或执行条件不同的变化不标成稳定提升。

## 测试选择规则（实施初始版本）

以下是应有的选择规则，不表示对应测试集或自动识别已经实现。各规则产出的实际测试集、版本、必要/建议属性、选题和未覆盖原因均应进入正式申请；规则找不到能执行的必要测试时显示缺口。

| 声明的改动 | 必要测试 | 建议扩展 |
| --- | --- | --- |
| 工具描述、schema、路由或参数 | 相关工具契约与安全检查、工具调用专项、使用该工具的链路 | 常规全量回归 |
| 某一业务链路或媒体能力 | 对应基础/契约、专项、链路及安全边界 | 与之相关的上下游和核心回归；真实媒体按费用、副作用分档 |
| 通用 Agent 循环、上下文、共享 Prompt、工具调度或模型 | 对应专项、安全及跨场景链路、常规全量回归 | 影响媒体或发布安全时追加相应完整回归；重要版本做完整基线 |
| Judge、评分证据或评分标准 | 固定样本正反例及历史证据重放、受影响评分契约 | 若采证路径或 Agent 行为也改变，增加相关真实链路验证；重判不计为 Agent 重跑 |
| 纯视觉与交互 | 相关界面状态、实际操作、返回刷新及响应式验证 | 若共享业务接线变更，追加对应业务链路 |
| 无法识别或影响范围不明 | 明确标记未覆盖，核对声明和改动清单，不给整体通过 | 补充相关领域测试或扩大回归 |

常规全量回归的成员应按实际调用链、成本和副作用核实；不是保证所有 DeepSeek 调用都无副作用。完整回归用于重要版本、周期性基线和影响全局或昂贵链路的重大改动，具体成员版本化，缺失或跳过的项目单列。可选执行不等于必要项通过。

## 计算与状态口径

- 每次正式运行记录计划数、已完成数和通过/失败/待复核/未运行；不适用与必要项未运行区分；基础测试、程序判断和语义 Judge 分开统计，安全关键失败单列；基础设施故障单列，不归咎于模型。只有题目对所有必要维度及关键门禁均有充分证据且明确通过，才能计为严格通过；此口径不取代独立维度分数，也不把不同维度加权平均。视觉稿的通过题数仅为严格通过示意。
- 单轮结果按冻结必要清单判断：存在必要安全项失败为未通过；存在其他必要项失败为未通过；必要项未执行、结果未知或影响范围未确认则未验证；存在待复核时标明待复核且不宣称通过；只有必要项均完成并满足规则时才标为通过。无关建议项的结果单独展示，费用和耗时不自动转换为通过/失败，除非该轮显式声明阈值。
- 统计分母和未知数量必须可见。通过率只针对已获得明确通过或失败的项目计算，并并列展示待复核和未运行；不能把未知当通过、失败或从覆盖分母悄悄删掉。无明确判定的项目无通过率。
- 跨轮比较先固定两个具体运行和可比共同题集；展示两边共同题、可评分题、缺测、失败/待复核。Token、耗时和费用只对双方均有同口径数据的共同题比较，并展示独立分母、计量来源与单位；样本不齐或不兼容时不显示误导性涨跌。用户可检查单题变化，不把不同集汇总均值冒充相同题对比。
- 每次运行留原始结果。首试、再次运行和试次规则分别标识；最近一次不是最好一次，展示此前失败。不同模型、判分、夹具或工具在目标范围以外的关键变化须明确提示；不存在充分证据时不推断因果。
- 部分题目的运行只声明覆盖这些题，不能显示整套通过。正式计划内不同运行若要合并覆盖，须同一冻结版本、规则和明确试次口径，逐项记录来源；重复题不叠加计数。若未满足合并条件则分开展示，缺失项保留未验证。
- 跨轮比较使用稳定题目身份及定义摘要；默认比较双方首试，预先声明的重复试验按对应试次展示，未配对或中断不剔除、不择优。两边已配对且均有实际用量时，分别对这些题的实际用量求均值并展示题数；平均耗时与费用同理，缺数据不设零、汇总差异不冒充逐题证据。

## 数据与接口边界

- 需要稳定区分：代码/配置版本、更新轮次、测试集版本、测试申请、每次运行、每题结果与证据。同一实例被多个集合引用不得重复计数；原题与自然改写是不同请求实例，同一实例的重试是不同运行/试次。身份至少包含实例 ID、冻结定义版本及运行/试次 ID；一个轮次可关联多种测试集和多次运行。
- 开发端可登记候选测试与临时结果；纳入长期正式测试集时，需有明确任务目标、初始状态、预期与证据、资源和副作用边界及可复现验证，并指定套件版本。重复风险相同的候选优先关联已有实例；源于真实使用的问题在入集前脱敏。规则或套件升级保留旧版本，既有批次不回写。
- 正式运行记录包含版本标识、代码/配置快照及其可恢复性状态、题集/评分/模型版本、选题、状态、环境和成本信息、原始证据及缺失原因。工件缺失不阻止登记失败结果，但该版本显示不可回滚和缺项；仅独立恢复演练通过后标为已验证可恢复。密钥不写入记录；个人素材先脱敏并限制访问。
- 不假定其他 worktree 的本地目录可被直接读取：正式结果需通过明确的共享归档或可验证的导入流程登记，校验身份、版本和证据引用，重复导入幂等；未导入不得声称看板已经收录。并行写入不得覆盖；运行中或损坏的登记显示异常，不能伪装成完成。
- 共享登记采用用户级可配置的单一权威本地存储，登记与状态更新须具备跨进程原子性、唯一 ID 和冲突检查；记录来源工作树与完整性摘要。先登记后执行，状态覆盖已登记、冻结中、运行中、完成、失败、终止和失联/未知；心跳失联不推断成功或自动重试。临时或离线记录允许后来补传，但明确标为补录，不伪装为事前正式登记。
- 旧批次按原有评分、冻结定义和证据只读展示；缺失项保留缺失。旧题集兼容接口和证据迁移策略需核对真实存储，导入不重算历史分数，无法关联更新轮次时归入历史记录。
- 重建期间先盘点旧批次和引用，保留源文件及旧读取路径；用一批代表性历史记录核对题目、原分、证据链接和缺失项后再替换展示入口。证据读取校验归属、路径和大小并脱敏，不把当前版本信息或文件时间推测为历史事实。

## 回滚

- 回滚目标是代码与配置；用户数据和评测历史继续保留。版本记录不仅有提交号，也必须有可恢复工件或经验证的快照；缺少依赖、模型不可用或数据契约不兼容时拒绝执行并说明。
- 先冻结新任务入口、检查执行中及已授权排队任务和外部异步副作用；让运行中任务完成。核对用户入口、Agent、后台 worker 和队列等实际入口清单，防止检查后新任务进入；若状态未知、等待过久或数据兼容性未验证，保持明确的阻塞状态，不擅自取消或重发。
- 完成兼容性检查后切换、验证服务，再恢复入口；失败时尝试恢复原运行版本并保留诊断证据，若无法恢复则保持入口关闭并报告。排队任务如何在版本切换后继续需按业务冻结输入与维护契约验证，不能默认安全重放。
- 以上是目标流程，并非现已实现的全自动回滚；不在当前讨论中执行停止、重启、迁移或回滚。

## 验收场景

1. 并行两条开发线各提交正式评测：看板都能看到，状态和版本不串；临时测试不会自动成为首页主项。
2. 一轮专项失败后重跑：两次记录均在，默认显示该专项最近运行；改代码后产生新轮次，不覆盖旧结果。
3. 两轮只共同执行部分题：只对可比共同题显示对比和分母；未测、缺证、评分版本变化分别呈现。
4. 专项通过但链路未跑，或者安全关键项失败：页面不显示整体通过，能追溯到原因和证据。
5. 测试读写隔离数据：并行运行不覆盖用户数据、其他评测及历史文件；真实/替身与费用信息如实展示。
6. 用户查看旧批次或选回滚：旧批分数不被重算；缺少可恢复工件、任务状态未知或数据不兼容时阻止执行并说明。
7. 页面覆盖加载、空、运行中、失败和窄屏，实际操作、返回与刷新后状态一致；外观和交互分别验证。
8. 共享登记失败时不可声称正式运行已登记；登记后冻结失败、进程中断和失联均可见。重复导入幂等，不同内容使用同 ID 冲突拒绝。
9. 单次仅运行套件子集时只显示部分覆盖；跨运行合并必须满足冻结版本与逐项证据要求。规则没有覆盖改动或必要项缺失时无法标整体通过；非必要项显示不适用。
10. 固定可比题分别构造缺失 Token、评分未知、不同夹具和重复尝试：页面显示各自分母/缺项，首试与后续运行均可查看，不将不兼容的项目计算涨跌。
11. 用隔离工件演练版本恢复：校验快照、依赖、业务数据兼容、入口和队列状态；模拟服务验证失败，保留旧版本恢复证据，无法恢复时入口保持关闭。真实运行中的用户任务不用于演练。
12. 键盘和移动视口可选择轮次、基准、运行和题目，展开证据、返回并刷新后选择仍正确；缺失或无权读取的证据显示原因，不泄露路径或敏感内容。

## 建议落地顺序

1. **统一记录**：先定义轮次、正式申请、运行和证据的版本化格式，实现共享申请登记与现有运行器的生命周期适配，覆盖冻结失败、启动失败和异常退出；先用受控样本验证，不声称跑通真实模型。
2. **一条工具评测闭环**：接入现有或另一个 session 建成的工具调用小集，支持隔离运行、结果留存及基线对比；用真实低成本模型验证时单独记录环境和费用。
3. **看板代表页面**：以轮次列表、单轮对比和一题详情跑通真实数据，再扩展空态、失败、窄屏与历史浏览；先确认代表页面的布局。
4. **扩充覆盖**：盘点并分配常规与完整回归，完善规则、成本数据和其他业务专项；按实际证据标记 Judge 未校准及待复核。
5. **版本恢复**：先独立核验快照可恢复性、数据兼容和维护控制，完成演练后才提供真实回滚入口；未满足条件前只展示回溯信息及阻塞原因。
