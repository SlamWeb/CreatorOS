# 可变规模 benchmark 题集协议

本协议只为题集定义、冻结、执行选择及报告提供宿主能力；新增的用例只有在场景夹具、用户请求、评分标准、证据和验证齐备后才算已实现，不能凭本文件或题目 ID 计数。

新版数据集显式提供：

```json
{
  "dataset_id": "creatoros-expanded-example-v1",
  "suite": {"version": "benchmark-suite-v1", "eligible_case_ids": ["C01", "C02"]},
  "cases": [{"id": "C01"}, {"id": "C02"}]
}
```

示意只展示新字段，不是可运行题目。真实 `cases` 必须继续提供完整的场景、任务、规则、家族、分组、来源和评分字段；同一 family 不得跨 dev / acceptance。`origin.type` 可以为 `trace`、`adversarial_variant`、`synthetic` 或 `fault_injection`。题号只能是大写字母开头的 1–40 个大写字母、数字、下划线或连字符，不能重复；`eligible_case_ids` 必须与案例按顺序完全一致，不允许用技术占位填充。旧协议无 suite 字段，继续严格要求有序 B01–B50 和既定 40/10 分组；自然 v1/v2 原有的 20 题显式资格限制也保留。

冻结时记录全部实际定义、家族和执行选集，选集必须为非空、唯一且属于当前题集；运行前重新验证源码、数据与选集。报告保留计划分母，并从冻结题集读取，不重算历史评分。只读 store 支持新题号，但题目必须属于相应批次才能读取其记录。拥有此 schema 不代表世界构造器和判分器已支持任意场景；每个新任务仍须单独验证实际执行和证据。

受限非视频守卫仍有单独的安全题目白名单；新题只有在核对外部副作用并显式加入后才能使用，不能将版本化题集当作网络沙箱。此协议也不解决跨套件家族分组泄漏，准备新题和合并套件时仍需检查原题、自然变体及相近题的来源与 split。
