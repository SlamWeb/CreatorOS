# 多阶段作品制作

## 通用 Agent 计划与持续执行（草稿）

- 用户明确希望 Agent 先制定待办并执行，复用已有 Skill 和工具，不增加专门的一键生图剪辑工具。一个实际计划可包含并行生图、等待素材和剪辑，也可以按任务不同而变化。
- 宿主须持久记录计划、已派发任务、依赖及结果；任务终态后继续，失败只阻断依赖，不重跑成功图片。账号隔离、指定 Skill/素材版本和显式停止保持可核验，旧任务不变。
- 用隔离真实 HTTP/SQLite、重启恢复、跨账号和幂等测试覆盖；真实 Agent 和 Codex 需验证能连续走通，受控夹具不能替代真实执行。

## 2026-10-27 简化 Skill 选择（已完成）

- 目标：账号添加 Skill，栏目选择账号可用 Skill，选题的每个制作任务直接选择栏目中的 Skill；界面不再要求用户理解主辅、Mind 或旧选择方式。
- 生图和剪辑仍是不同的任务及产物类型；现有任务、冻结版本及历史产物保持可读。后台兼容旧字段，用户明确选择的 Skill 版本和资源须冻结。账号归属与栏目范围继续校验。
- Given 账号已添加剪辑 Skill、栏目已选择该 Skill，When 在对应视频任务中选择它，Then 不因缺少输出声明而隐藏或拒绝；Given 两个制作任务各选择不同 Skill，Then 各自仅冻结所选版本。Given 旧任务运行或重启，Then 不改其输入也不自动重跑。
- 验证：隔离 SQLite/真实 HTTP 检查权限、版本和历史兼容；浏览器实际完成添加账号、配置栏目、选择任务 Skill，并单独核对视觉截图；不自动生产或发布正式内容。
- 已实现并验证：后端 60 项定向回归通过，旧 role 任务保持原验证和提示词；新 skill_ids 可选择未声明输出能力的 Skill，并冻结每份原文与资源。Agent 的栏目池编辑不再要求主辅；新建栏目只填名称。
- 隔离浏览器测试：拆分任务 3/3、账号库及栏目池/视频/旧 Run 5/5；用户已有 Qa 栏目只读核对 image-beat-story v1/v2 均在每项选择列表。正式服务空闲后已重启，旧任务未重跑。
- 真实 Codex 剪辑验证：无输出声明的原版 image-beat-story 经新 skill_ids 完成视频，中途命令失败后同线程自修，详见 [VALIDATION.md](VALIDATION.md)。

## 2026-10-27 实现与验收

用户授权按已讨论顺序重构：账号可用 Skill 库、栏目常用池/阶段默认、每次任务明确 Skill 与输入输出；同一选题批量生图收集后，ZIP+BGM+剪辑要求交新 Codex thread 产视频；最后持久依赖自动续接。旧记录/图片/RSI不改，不自动重跑。保持现有配色。

## 契约与分工

- 账号库与栏目池保存 Skill 家族引用，不复制文件；栏目池是常用子集，不是账号权限来源。旧绑定作为生图默认兼容读取。版本选择必须冻结正文和全部资源，候选可显式试用。
- 新执行规范 TaskExecutionSpec：kind=image|video，skills 为准确 skill_id/digest/role(primary|supporting) 列表，materials 为宿主解析和冻结的材料。角色和产物类型分离，旧 Mind/production 记录继续可读；主 Skill 必须符合本任务输出能力，辅助 Skill 不强求可独立生产。
- ProductionTask 沿用一个 Topic 下独立 Run 的模型；新增 kind、definition_json、dependency_json、dispatch_state、last_error，用于等待材料、一次提交和恢复。依赖只指向本选题明确选中的生图任务，不按全账号历史推断；等待中没有 Run。已成功 Run 不重跑。
- 模型/HTTP 任务输入只接受对象 ID：任务 kind、title、brief、所选 Skill 及 digest，video 的 collection_id/export_id、bgm_material_id 和 depends_on。不能由模型传主机路径。宿主准备固定 ZIP/音频后才生成执行规范；没有输入时明确等待或报错。
- 素材上传先支持 MP3/常见音频或视频文件；分享链接作为 BGM 来源受管解析，实际取得的文件要冻结。链接无法解析时明确要求上传文件，不声称已具备音乐。
- 视频首次使用新 Codex thread，技术恢复续接同一视频任务；共用 Run/Revision/Attempt、队列、租约和事件，按 kind 分派准备/执行/验收。MP4 不伪装成图片 SocialContentPack；需要真实解码、时长、尺寸、音轨及摘要校验。
- 无通用工作流画布；自动衔接是持久后台任务，不让聊天 LLM 反复轮询。可人工选片后提交，也可显式授权等待既定生图任务完成后自动导出并剪辑。失败/缺图不静默跳过。

## 验证边界

已授权验收边界：真实隔离 HTTP+SQLite 账号库/池/任务/导出接口，现有旧记录和文件保护；故障注入测重复请求、等待/恢复与跨账号拒绝；真实前端 DeepSeek 提交，真实 Codex 使用图片/BGM制作短 MP4，页面播放/下载。受控测试不替代真模型证据。正式服务更新前只读检查运行与排队，忙则不动；有迁移先备份并按维护流程验证。

## 步骤

1. 账号/栏目 Skill 引用与统一任务输入，隔离验证并提交。
2. 视频材料、执行/交付/页面，真实链路验证并提交。
3. 持久依赖续接、权限/幂等回归、旧分支适配收敛并提交。

## 已落地

- 三项数据库迁移：账号库/栏目池、持久阶段任务与受管素材、只填名称的栏目。旧栏目仍可读，显式阶段默认优先；旧产物输入快照不变。
- 一个选题下的制作任务分别选择主 Skill 与辅助 Skill；图片沿用 native 收图，视频使用独立 MP4 交付类型，但共用现有 Run/Revision/Attempt、队列与恢复。没有另造工作流引擎。
- 视频任务提交即冻结 Skill 与 BGM。等待明确选中的图片版本，全部完成后才固定 ZIP、建新 Run 和新 Codex thread。失败待核对，显式重试；成功图片不重新生成。
- Web 提供账号库、栏目阶段默认、拆分制作、素材选片/BGM/剪辑、播放下载与验收。无 Run 的等待任务也进入任务铃铛、账号任务与 Observation。
- Agent 复用 start_content_run 的 typed tasks；新增 manage_skill_library/manage_material 对象级工具。相同人类消息中的不同阶段分别有幂等键；同内容重试复用原任务。摘要可由宿主解析，不要求模型抄长哈希。
- 普通单选题生产使用栏目当前图片默认；普通单 Run 从头重做重新解析当前默认；独立制作任务保留自己的明确选择，视频不能被旧图片覆盖参数静默转换。普通返工保留旧任务快照。

真实链路与开发中失败均记在 [VALIDATION.md](VALIDATION.md)，使用入口见 [USAGE.md](USAGE.md)。目前验证的是两张图到六秒视频，不代表百图规模性能或任意分享链接解析能力；没有自动发布或通用每日定时流程。
