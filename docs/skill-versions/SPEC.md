# Skill 版本管理

## 契约 · 2026-10-21

- 一个版本是一份完整 Skill：正文、assets、scripts 共同复制和计算摘要。旧登记 ID 保持不变，现有工作副本作为 v1；候选拥有独立 ID，不覆盖旧文件。
- 栏目继续绑定准确的 Skill ID，不新增可变的“最新版本”指针。编辑先产生候选；干净 Codex 线程试用当前摘要，用户明确确认后才切换选定栏目。其他栏目、已有 Run/Revision/Attempt 和排队输入不变。
- 已发布版本只读；再次修改另建候选。历史版本可直接回退。切换使用栏目 revision CAS 和持久化请求回执；失败不宣称切换成功，重放不重复执行。
- 复用既有独立草稿试用队列，不引入优秀作品池、DS 校准、自发规则提取或新的生产模式。旧校准保存入口不得继续原地覆盖共享 Skill。
- HTTP：Skill 下 versions（历史/创建）、version-trials（试用）、publish-version（保存）；栏目下 skill-version（切换/回退）。发布和切换仅人工入口，账号 Agent 可以读写所属 Skill 家族的候选，不能自动激活。
- 验证：隔离文件/SQLite 的正文与多 assets、CAS/重放、试用后再编辑、搭档/栏目变更、历史回退、旧 Run/文件不变；隔离浏览器操作与真实 Codex 试用分开记账。不写正式业务资料，不中断在途任务。

## 实现与证据

- `skill_versions.py` 管完整目录及不可变登记；`SkillVersionService` 管冻结试用和栏目切换。沿用 Series 的准确 Skill ID，无数据库结构迁移。编辑发布版自动另存候选；发布与切换仅人工入口。多版本家族暂不开放删除，防止丢失历史与旧排队输入。
- 旧校准 apply 仍验当前草稿/实际试产/搭档，再发布独立版本并只切当前栏目；持久化切换意图可恢复。旧版本文件始终不原地 rename；仅过去遗留的旧发布意图保留原恢复语义。
- 生命周期/作用域/资产定向 44 项通过（含故障注入；不算真实模型成绩）；旧校准 24 项通过。额外 ACL 发布顺序、短目录/旧目录兼容、Observation 与旧删除入口保护均有回归。受控模型仅负责本地故障和确定性接线。
- 独立审查补三条边界：先发布而 SQLite 切换失败不能绕过首次试用；A 栏目使用过不能作为 B 栏目的免试回退权限；无关旧栏目缺失 Skill 或试用索引损坏不阻塞健康历史。
