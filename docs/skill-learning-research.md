# 从优秀作品与失败产物中校准 Skill

调研日期：2026-10-19。状态：研究与后续建议，**没有实现自动学习、训练或质量提升实验**。

## 论文实际在做什么

[Skill Training with Corruption and Reconstruction Loop（arXiv v2）](https://arxiv.org/abs/2607.27557)
迭代的是外部文本 Skill 库，不更新模型权重。它先将专业剧本压成保留情节的大纲、移除对白/动作/节奏细节，再让模型借助 Skill 重建；对照同一故事原稿与重建稿的差距，更新相关规则卡。

这不是“任何坏产物都能自动总结成好经验”：有同一任务的优秀参照，才较容易判断缺了哪种技巧。该工作验证短剧文本，不能直接推出漫画/IP一致性也会提高。[官方实现与结果边界](https://github.com/skilltraining-project/skill-training#results-from-the-paper)

## 对本项目最重要的不是再增加一个反思 Agent

官方 [backward 提示](https://github.com/skilltraining-project/skill-training/blob/main/prompts/backward.md)
先检查实际读文件记录：已有规则未被读取是路由问题，不应再新增重复规则；只在一个故事出现的问题，不足以修改全部任务通用规则。

今天 CreatorOS 的问题要先分开归因：

| 证据 | 应改的位置 |
| --- | --- |
| 用户点名 few-shot，但调研只拿到摘要 | 输入资料交接 |
| 保存了来源档案，实际主 Skill 未同步 | 编辑目标及引用 |
| 原图人物关系理解错误 | 原作解读，先人工纠正 |
| 样例正确送达并使用，故事仍空泛 | 创作方法候选改进 |
| 成品有文件，但缺教学文字/应有版式 | 交付完整性，不能只判文件可读 |

不能用“模型要自我进化”掩盖前两类接线错误。

## 建议保存三种资料，暂不自动覆盖 Skill

- **优秀范例**：完整图组、核对过的逐页文案/镜头、用户认可的原因、来源与使用权限。
- **失败案例**：任务原话、当时 Skill 快照、实际读取的资料、产物、用户具体批评。不要只有“很差”或将所有失败都归 Skill。
- **候选经验**：依据哪对范例与失败、适用场景、具体修改、版本差异与试用结果；用户认可后才入库，可回滚。

例如原作最后把开头的蛋糕送给别人，生成稿却以“不要比较”结束，可提出“用开场道具完成关系层面的行动回扣”这一候选经验，并保留具体镜头对照；不能只加“温暖、有趣、不要鸡汤”。这是项目建议，不是已证实的泛化规律。

## 最小可检验步骤

1. 一个系列先准备2～3个已认可的完整故事，另留未参与修改的故事或新选题。
2. 冻结原 Skill，先在文字故事阶段比较，不默认每题先生成整组图片。
3. 原版/候选版采用相同模型、输入、页数条件和可见参考；记录实际使用资料，检查重复、因果、转折和结尾动作，并由用户盲选。
4. 显示 Skill diff 与试用结果，明确确认后更新；旧版本与失败记录保留。
5. 只有故事改善后再验证图文/IP，不能用训练故事重建更像原作冒充新选题更好。

正常生产可以直接看完整优秀范例；只有要检验“是否学会补回某种细节”的重建练习，才隐藏那些细节。两种任务不能混为一谈。

官方 [运行与对照指南](https://github.com/skilltraining-project/skill-training/blob/main/docs/guide.md)
保留原稿、重建稿、loss、实际读文件轨迹与 Skill diff，并要求留出材料检验泛化。其原稿泄漏检查是轨迹检查，不是操作系统级隔离；开源示例也不等于公开了论文全部专有语料。

## 与本轮实现的界限

本轮只把原始 Mind＋Visualize 直接绑定作为默认，并补 Mind 引用文本示例进入调研快照。已有融合入口仍显式可用；不迁移正式栏目、不修改共享 Skill、不自动根据今天失败生成新规则。

后续优秀库应该保留完整证据、按场景选择少量相关例子；不把全部作品塞进每次上下文，也不把失败日志堆进 SKILL.md。
