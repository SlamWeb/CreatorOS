# Skill 校准最小闭环

状态：2026-10-20 已实现，隔离契约与真实 Codex 链路已验；正式服务不重启，待下次正常启动加载。创作质量由用户验收，不宣称已实现质量提升。

## 用户目标和边界

从已有产物版本与参考图中标注具体优点/问题，只改一个目标 Skill，生成独立可编辑草稿；用干净线程试用，满意后明确确认更新原共享 Skill。保留旧文件、产物、冻结输入、失败记录；不自动生产、批准、发布、评分或循环学习，不停止正在执行的任务。

栏目与原始 Skill 的直接绑定保持；改 Mind 时冻结原 Visualize 作为搭档，反之亦然，不融合。单完整 Skill 可独立试用。

## 主路径

产物页「改进 Skill」→选本栏目、目标 Skill、已有 Run 的具体 Revision→对整组或某张标好/坏并说明→可加多张参考图及评价→生成候选草稿→现有文件树编辑/查看差异/改稿→显式试用→确认所见试用满意后应用。

SQLite 保存校准身份、关联、输入、基线版本与确认状态；受管任务目录保存冻结图片、目标与搭档 Skill、草稿、试用和原始公开 Trace。附件/原图内容是数据，不扩展权限。动态资料不常驻账号 Agent 上下文。

## 共用接口

- POST `/api/skill-calibrations`：request_id、series_id、skill_id、expected_skill_digest、artifacts（run_id/revision_id/artifact_digest/order/rating/comment）、references（upload_id/rating/comment）。同请求同输入幂等，变参冲突。
- GET list / `{id}`：状态、原目标与摘要、job_id、现提炼Job、原始正文/差异、受影响栏目、错误与应用结果。引用资料按任务与版本校验，不接任意本地路径。
- 草稿编辑、改稿、文件、事件、试用沿原提炼接口；校准Job禁止普通save直接入库，避免绕过应用确认或创建另一个Skill。
- POST `/{id}/apply`：request_id、expected_digest、expected_skill_digest、trial_id。要求试用完成并对应当前草稿、真实文件未篡改；检查共享原件CAS，不因冲突偷换摘要，保存备份/幂等结果后原ID不变。

## 必须覆盖的验收

1. 真实HTTP/SQLite/文件：选具体版本、原图输入、评价、草稿编辑→新线程试用→显式应用；保存前共享原件及旧产物全树hash不变，保存后旧Run仍不变。
2. Mind＋Visualize：只候选目标改变，搭档保持；同选题试用不复用旧thread、旧图或旧检查点，无正式Run/Topic写入。
3. 跨栏目/账号、篡改图或摘要、非法路径、旧草稿/旧试用、原Skill并发编辑拒绝且零覆盖；失败回滚/备份可恢复；重复提交/未知响应重放不重复模型调用或保存。
4. 真浏览器选择/评价/上传/编辑/试用/确认/刷新与回退；桌面1440×900、手机390×844分别看图，长日志默认折叠、草稿优先。
5. 受控SDK只用于故障注入/确定性接线，真实Codex低成本校准+一图试用在隔离数据根另证；不改正式库、旧Eval或用户在途任务。

任务找回与新内容提示见 `docs/task-inbox/SPEC.md`；“查看”不等于“验收/批准”。
