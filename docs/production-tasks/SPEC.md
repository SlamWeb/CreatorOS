# 选题内制作任务

## 2026-10-27 实现与边界

用户授权直接实现：一个选题拆成多个制作任务，每个任务独立选择 Skill、并行生产，收进同一个素材集；剪辑下一步接。

- 新增 ProductionTask，隶属于真实 Topic；ContentRun.task_id 可空，旧 Run 保持空，不回填、不改旧快照和产物。
- 任务记录名称、要求、顺序与冻结的 Skill 选择。缺省使用提交时的栏目绑定；可指定完整 Skill 或 Mind + Visualize 组合，不改栏目默认。
- 新任务按 task_id 隔离生产/重做/互斥；旧 Run 继续按 Topic 隔离。复用原 Run、Revision、Attempt、持久队列、并发限制和收图。子任务不得互相覆盖父 Topic 状态。
- 批次使用 request_id 幂等，创建任务和 Run 原子提交；失败独立显示、重试走原 Run 的恢复/重做，禁止为重试新建父选题。
- 一个父选题关联一个专用制作素材集，只自动聚合制作任务的当前 Run/当前版本；旧 Run、失败记录和其他版本仍在原页面。按任务顺序、图片顺序收集，不按完成时间排序；复用现有选片、排序和 ZIP 导出。
- Web 在选题详情中增加拆分制作与任务清单；旧无子任务卡片行为不变。Agent 通过对象级工具创建/读取制作任务，沿用账号归属权限。
- 本轮不实现剪辑、不创建通用工作流引擎。账号 Skill 库仅设计：账号可用库提供候选，栏目提供默认，制作任务锁定具体版本。

## 验收边界

隔离 SQLite/输出目录验证迁移、并行作用域、请求重放、不同 Skill 快照、单任务失败与素材排序；真实前端使用 DeepSeek/Codex 验证两任务生产链。正式数据库、旧 RSI、图片、分数和运行中的服务不修改、不重启。

故障与并发测试可使用受控生产器注入失败；此类测试不作为真实 Codex 效果证明。

## 已实现的契约

- GET/POST `/api/topics/{topic_id}/production-tasks`；POST 使用稳定 request_id 和 tasks（1–100 项）。一个批次的 Task、Run、Revision、队列授权、素材集和回执同时提交。同键不同内容拒绝；相同请求仅返回原任务，不再授权执行。
- `start_content_run(topic_id,tasks)` 复用现有模型工具；`manage_topics(get)` 仅当有子任务时附加任务列表，模型只接收名称、Skill、状态和入口，完整 brief 留在实际输入与 Trace。
- SQLite 新表 `production_tasks`，旧 `content_runs` 仅追加 nullable task_id 与索引。新任务可和同父选题的兄弟并行；同 task 的旧执行线程真正退出前不开始下一次。
- 普通旧 Topic/Run 路径不变；只有新拆分且无旧 Run 的父选题不再提供整题“开始生产”，避免误生成一份覆盖全部场景的重复任务。
- 普通恢复复用原冻结目录；子任务从头重做默认保留自己的完整 Skill 选择和 digest，不偷偷换成栏目默认。显式指定新版本才替换。候选正文/素材变了则要求重选，不静默接受新字节。旧 legacy fresh 仍按原逻辑使用栏目当前版本。
- 专用素材集默认选择每个任务最新 Run 的当前版本，按 task.position、图片序号排列。旧图继续存在于旧 Run/版本；可以通过既有来源管理显式加入。重做尚未交付时该项显示等待，不把旧图冒充新版。
- 账号/栏目转移后冻结归属不符的任务不泄露、不复用旧素材集。RSI、父选题移除/编辑的在途保护仍保留。

## Skill 库的下一步设计（本轮未实现）

账号拥有“可用 Skill 引用清单”，不是复制一份所有共享文件。栏目从清单中设置默认组合；制作任务可以沿用，也可以选另一份可用版本，并在提交时冻结正文、assets、scripts。将来剪辑任务从同一清单选择剪辑 Skill，输入是本轮素材集的固定 ZIP 加 BGM；生图任务只取它需要的 Skill，不加载剪辑规则。

当前任务仍支持现有完整 Skill 或 Mind + Visualize 组合，没有任意多 Skill 自动融合，也没有通用工作流画布。账号 Agent 本轮沿用既有账号可访问 Skill/候选权限；共享库的新授权模型单独接，不借此绕过其他账号的候选边界。
