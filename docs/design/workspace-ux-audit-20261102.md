# 工作台真实操作审查 · Assessment A

审查日期：2026-11-02。独立审查者：`/root/workspace_ux_judge`。本文件仅为设计判断与真实操作证据，供主审与独立代码检查合并；不是完整双评估结论。

目标：`web/src/pages/WorkspacePage.tsx` 对应的**当前已部署** `http://127.0.0.1:8765/workspace`。使用独立后台浏览器标签，不复用用户标签；未改产品代码、未重启、未创建/删除业务对象、未触发生产/调研/提炼/发布、未调用付费模型。打开创建入口后均取消。

## 整体判断

主要问题是工作对象与操作位置没有对齐，不是缺一个组件库。账号、栏目、选题三个层级已有，但导航把所有账号的所有子栏目同时铺开；创建表单又放到整棵树末尾；设置则插进内容顶部。用户每做一步，都要重新判断“我在哪里、改的是谁、内容去哪了”。只改滚动条、圆角和 Tabs 不能解决这些问题。

建议先收束为：**先选账号 → 只展开当前账号栏目 → 右侧始终保留当前工作对象；创建与设置在明确归属的独立面板完成**。搜索、细滚动条、按钮样式属于这之后的第二步。

本页不是毫无优点：

- 主导航一直可见，账号/栏目切换能更新对应内容和 URL；无需穿过独立后台页面才能换账号。
- 栏目页的任务默认收起、顶部已有分页，“调研选题 / 添加选题 / 栏目设置”也能明确找到。应保留这些进步，不回退到长期展开所有任务和设置。

## 发现（按优先级）

### A1 · P1：整棵账号栏目树常驻展开，定位成本随账号数增长

- **步骤**：从首页进入工作台；查找列表底部账号并打开；再切换该账号的栏目。
- **观察**：首屏同时列出多个账号和每个账号下的栏目；底部账号与“新账号”在内层滚动区外侧不可见部分。没有搜索/过滤，也没有账号折叠入口。当前列表包含8个账号、多组子栏目；账号与栏目都主要依赖文字、粗细和很小的缩进区分。
- **影响**：找一个目标需要扫描无关账号与栏目；不能一眼看见全部账号；用户已记住名称仍必须滚动寻找。长列表会持续恶化，单纯把滚动条变细不减少搜索量。
- **建议**：账号选择与当前账号的栏目列表分开；或账号可展开且默认仅展开当前账号，记住上次展开状态；提供统一名称过滤。选中栏目必须同时让所属账号可识别，不只给子项灰底。
- **证据**：`tmp/workspace-audit-20261102/01-workspace-empty.jpg`、`06-series-content.jpg`。确认为真实操作；未做计时与用户招募研究。

### A2 · P1：右侧“新建栏目”把表单送到整棵树最底下，归属容易看错

- **步骤**：在空账号右侧点击“新建栏目”。
- **观察**：右侧空态仍留在原处；左栏自动滚动到底部，在最后一个账号栏目之后显示“栏目名称 / 创建 / 取消”。真正的当前空账号已不在可见树区域。表单自身不显示“为哪个账号创建”。
- **影响**：操作从右侧跳到左下角，用户视线丢失；表单视觉上更接近底部另一个账号。即使后端归属正确，也会让用户不敢点创建，或误以为正在给别的账号添加。
- **建议**：使用固定位置的对话框/侧面板，标题直接写“新建栏目”，紧跟只读归属账号或明确账号选择；账号行的“+”和右侧入口都打开同一表单。创建完成后定位到新栏目。此处不需要更多解释文字。
- **证据**：`tmp/workspace-audit-20261102/03-new-series-detached.jpg`。已打开并取消，未提交。

### A3 · P2：新账号入口藏在树尾，打开后表单又被内部滚动区截断

- **步骤**：点击树尾“+ 新账号”。
- **观察**：入口被替换成内联表单，有账号名称、账号标识、创建、取消。截图中可见顶部名称输入，后续字段和按钮落在面板下边缘之外；需要继续操作内层滚动才能完整看见。
- **影响**：找入口已经要滚到底部；打开后还要再滚才能完成；用户容易把“没看到按钮”当成页面没响应。技术性的账号标识也增加了创建心智负担，但本次没有提交验证它是否必填。
- **建议**：在账号选择器顶部提供一个稳定“新建账号”入口；表单放对话框并一次完整显示名称、必要字段及取消/创建。不要让表单参与长树的布局。
- **证据**：`tmp/workspace-audit-20261102/02-new-account-inline.jpg`。已打开并取消，未验证字段规则。

### A4 · P2：栏目设置占据主内容流，打开后选题消失到首屏以下

- **步骤**：进入有38条选题的栏目 → 点击“栏目设置”。
- **观察**：设置展开于栏目头部与卡片之间。改名、账号归属、删除、Skill选择、版本选择及两个保存按钮占满当前右侧屏幕；原来可见的选题卡片被推到下方。Skill左侧复选项与右侧版本选择相隔很远，保存名称按钮与输入框底边也不齐。
- **影响**：用户从看内容切到设置后丢失原来的选题位置；保存范围被拆成多个局部动作，视觉上像一页管理表单。该问题的代价是内容定位，而非“灰按钮不好看”本身。
- **建议**：栏目设置放右侧抽屉或对话框；信息按“名称和归属 / 栏目Skill”清晰成组，Skill名称与版本一行对齐；危险操作独立放底部。关闭后回到原选题滚动位置。
- **证据**：`tmp/workspace-audit-20261102/06-series-content.jpg` 与 `07-series-settings.jpg`。只展开未修改。

### A5 · P2：素材文件夹只有名字，同名素材集无法辨认

- **步骤**：打开同账号“素材”标签。
- **观察**：素材文件夹显示成多行小按钮，其中两项拥有完全相同的名称；未选中前没有缩略图、图片数、时间、所属栏目或制作状态。
- **影响**：用户不知道哪个是要给视频用的那批，只能逐个进去排除；账号积累素材后，名字不足以支持选择。一个用于批量创作的系统需要让素材成为可识别对象，而不是一串同样的按钮。
- **建议**：素材入口改为简洁文件夹列表/卡片，至少显示封面、名称、图片数、最近更新时间；同名时补所属栏目或日期。保留一次点击进入，不要先增加二级说明页。
- **证据**：`tmp/workspace-audit-20261102/04-materials-repeated-names.jpg`。确认同名和缺乏区分信息，未核对两个集合内容是否重复。

### A6 · P2：全局 Skill 与账号 Skill 的边界靠用户记忆，账号库操作排版不稳定

- **步骤**：进入账号“Skill 库”；观察左侧主导航与本地标题；查看已有 Skill 列表。
- **观察**：左侧主导航“Skill”和账号标签“Skill 库”并存；账号内另有“管理已安装 Skill”跳到全局。账号列表中一行的“移出账号库”在当前1280级桌面窗口换成两行；描述长、版本小、移除按钮蓝色，与查看链接接近。
- **影响**：用户需先知道全局安装→账号引用→栏目使用这套内部模型才能判断去哪找 Skill；同一行的核心对象与移除动作不成稳定布局。这里不能只靠改名称解决全部信息架构问题。
- **建议**：主导航明确为“全部 Skill”，账号内保留“账号 Skill”；列表使用一致的名称/版本/简短描述/更多菜单四区，移除归入更多，留出固定动作宽度。新增选择支持搜索，避免长原生下拉。
- **证据**：`tmp/workspace-audit-20261102/05-account-skills.jpg`。未点“移出”，未更改版本。

### A7 · P2：栏目页任务数量缺乏可见范围说明，容易被当作当前栏目任务

- **步骤**：从账号内容进入一个栏目；观察最上方“任务 待批准120 失败9”；再切到另一个账号栏目。
- **观察**：栏目页头部仍出现账号级任务汇总，但“任务”旁没有账号/栏目范围文字；页面右侧显示当前栏目名称。另一个账号的栏目变成另一组汇总数字。顶栏还有另一枚铃铛任务入口。
- **影响**：用户看见栏目页的120条待批准，可能误以为都是这个栏目；两个任务入口的职责不可凭画面直接分辨。造成压力与找任务的额外试探，不是本次证明了数字计算错误。
- **建议**：栏目页汇总按当前栏目呈现，或标题明确“账号任务”；顶栏只保留全局通知，内容区只保留当前范围的工作入口。不要仅给两个入口换相同组件。
- **证据**：`tmp/workspace-audit-20261102/06-series-content.jpg`，以及真实切换后的另一组任务数。**范围归属结论只基于切换表现，尚未逐项打开任务列表核对**。

## 认知负担与可发现性

- 导航让用户同时面对8个账号、多组子栏目与5项主导航；按账号找到内容的决策点超过4个选项且缺少搜索。问题是无关对象竞争，而非必须把所有列表限制成4项。
- 栏目首屏的主要内容是选题，但任务汇总、栏目Skill、三个动作、条数、刷新、选择、分页占据上半屏。更合理的是保留栏目名称与两个创作动作，其他围绕内容作为次级控件排列。
- 空账号首屏有一句明确空态和一个创建动作，这是正确方向；大面积实心灰块并不能让下一步更明确。可缩短容器，将“新建栏目”放在稳定位置，图标仅作为辅助。
- 对常用者，反复的滚动与对象定位比按钮颜色更伤效率；对首次使用者，“Skill在哪层、新建给谁”则更致命。
