## 判断

优先修的是工作对象与操作位置：先选账号，只展示当前账号的栏目，创建表单明确属于谁，内容不被设置挤走。现在的核心问题不是 React 或组件库不够好，也不是缺少装饰。已有三栏结构可以保留，不必重写生产、聊天、路由和数据层。

产品特征已有：账号、栏目、素材、Skill 与 Agent 联动是真实业务结构。但导航与创建方式仍像把后台对象直接铺成表格，尚未围绕创作者的“找到栏目 → 看作品 → 下一步操作”组织。

## 优先级与证据

| 优先级 | 问题 | 用户影响 | 建议 | 证据 |
|---|---|---|---|---|
| P1 | 所有账号及子栏目常驻展开，没有搜索 | 账号越多，找当前对象越费劲 | 账号选择器可搜索，下面只显示当前账号栏目，保留账号概览及未分配栏目入口 | A 实操、B 源码一致 |
| P1 | 右侧新建栏目，表单出现在整棵左树末尾 | 当前账号已滚出视野，表单靠近另一个账号，看不出归属 | 所有创建入口打开同一可见面板/对话框，显示所属账号；新账号入口固定可见 | A 已打开并取消、B 源码一致 |
| P1 | 有栏目但没有选题，空态仍引导新建栏目 | 下一步方向不对，重复创建容器 | 无栏目时建栏目；有栏目时进入已有栏目添加选题 | 仅 B 源码确认，未在真实现存数据中复现 |
| P2 | 设置展开后占据正文顶部 | 想看内容，却需要继续下滑 | 栏目设置独立侧面板，标题与常用动作固定清楚 | A 已打开、B 确认默认收起 |
| P2 | 同名素材集缺少辨认信息，Skill 的全局/账号范围不清 | 选择依赖记忆，容易拿错对象 | 素材显示封面、数量、来源栏目、更新时间；Skill 明确当前账号范围和移除语义 | A 实操，未提交移除 |

对应适用的设计工作：前两项以 layout/shape 为主，空态以 onboard/clarify 为主；不要先 animate/polish 再处理结构。

另外两项需要整理：导航被装在通用正文版心里，产生横向空白；任务摘要的统计范围在界面上不明确。后者需要先确认数据范围，再补准确标签，不能据此宣称统计错误。

## 已经有效的部分

- 主导航稳定，账号/栏目有 URL 身份，切换并非临时本地页面。
- 任务默认收起、设置默认收起，选题已有顶部分页。账号预览为每栏目 6 条，完整栏目每页 20 条；不能继续以旧版每栏目 20 条为审查依据。
- 聊天宿主在 Layout 层，会话与草稿跨导航保留。导航改造需要保住这一点，无需重写 Agent 面板。

## 对 Gemini 建议的取舍

- 细滚动条可以做；ScrollArea 不是前置条件。减少无关栏目同时出现，比隐藏滚动条更重要。
- 树状竖线可帮助识别父子，但不能代替账号切换和渐进展开。不要仅给长树换皮。
- 更多操作可在 hover 显示，同时必须支持键盘 focus 与触屏，不能只给鼠标用户使用。
- Tabs 统一值得做，底线是选中态清楚、URL 与返回行为保留；胶囊本身不保证更好。
- 空态先改正确入口，再处理图标与虚线框，避免继续添加解释性文案。
- React/TS/Tailwind 已具备；公共 UI 基础目前主要是 Button/Input/Textarea，不等于全站已经统一使用 shadcn。不要为此次导航改造做全站组件迁移。
