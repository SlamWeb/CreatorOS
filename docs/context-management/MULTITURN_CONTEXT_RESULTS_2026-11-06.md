# 跨轮上下文与缓存：隔离真实模型对照（2026-11-06）

## 方法与边界

仅使用合成数据，在两个独立临时会话中分别运行旧版 `1bc0e65` 的 `run_agent` 与当前工作树的候选实现。调用真实 `deepseek-flash`（非思考模式），各执行一遍相同语义的七轮请求，顺序先基线后候选；每组各自生成不同的随机填充前缀与随机作品标记，避免直接互相命中。每两轮之间固定等待 5 秒供缓存持久化；这个人为等待不计入下表的用户轮耗时。缓存仍是 best effort，其他请求可能影响服务端缓存，不能用一次顺序固定的实验推断统计显著性或生产平均。

场景按顺序覆盖：①收到选中作品资料但不复述暗号；②追问作品暗号；③栏目绑定 Skill V1 改为 V2 后询问之前和当前 ID；④同一 Skill ID 的 description 变化后询问前后值；⑤此前计划提交 unknown，判断能否重试或发布；⑥拒绝读取另一账号；⑦历史助手的音频导入说法与宿主当前生产能力事实冲突，回答当前能力。基线和候选均不允许真正派发模型请求的工具；一旦模型尝试调用，即由测试 guard 拦截并记录。第 ③/④ 轮通过变更测试内存里的宿主目录模拟外部状态变化，**没有实际执行栏目或 Skill CRUD，也没有验证磁盘上 Skill 正文变更**。旧版与候选除 loop 外共享工作树中本次其他依赖，属于受控的组装对照，不是两套完整发行版本的对照。

实际账号隔离另外使用临时 SQLite、动态端口 loopback HTTP 和真实 `manage_topics(get)` 入口：另一账号资源读取被拒，测试业务行前后相同，Run 和生产调用均为零。这一探针与模型只回答拒绝不是同一个证据。所有目录与数据仅为临时测试夹具，不读取或重放正式历史任务，不发布、不生图；结果不记录标记原文、账户正文或密钥。

复跑命令（明确加 `--live` 才调用付费模型；报告路径必须是新文件）：

```powershell
D:/Anaconda4.7g/envs/deepcode/python.exe -m tests.live_context_multiturn_compare --live --env-file D:/CreatorOS/.env --report tmp/<new-dir>/report.json
```

默认不加 `--live` 不调用模型。脚本按轮保存匿名进度、usage、耗时和异常类型；该次完整报告位于忽略目录 `tmp/context-multiturn-comparison-20261106-r1/report.json`，按本次结果原样保留，没有自动重试或挑选成功记录。此前仅执行不付费的基线 fake Provider 六轮预检、候选 fake Provider 六轮预检与单独的真实工具作用域预检；这些不计入以下有偿结果。真实对照由旧到新各一组，两个会话的 system 随机填充内容不同，完整 token 数与计时有随机差异。

## 真实工具接线补验与失败记录

单独运行 `tests.live_context_integration --live --env-file D:/CreatorOS/.env`，以独立 SQLite 和真实 HTTP/工具派发验证选题 list/get，不允许生产和跨账号读取。第一次运行虽然通过答案中的两条标题与随机标记检查，但未满足“实际执行过 list 和 get 且均无错误”的断言；当时断言未记录具体动作，因此不能确定是模型复用列表预览、遗漏 get 还是其他调用问题，亦不能把它写成通过。分析发现夹具原先把标记放在列表预览内，模型有机会不读详情就答对。

随后将标记移到列表预览以外，并使失败断言输出脱敏的动作和错误标记；第二次使用新隔离夹具通过：两轮 4 次模型请求，真实 list/get 各一次，详情标记与两条标题正确，同轮两次结构比较均为追加，跨账号读取被拒，业务行不变、生产调用为 0。实际 input/output **27,215/269**，cache hit/miss **25,856/1,359**。首请求有缓存命中，可能来自之前实验，不能视为冷缓存对照；该次不同夹具的重跑不能抹去第一次失败，也不能据此认定真实模型永不跳过显式工具调用。
