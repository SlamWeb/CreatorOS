# 上下文归因基线（2026-11-05）

## 范围和可复现性

本基线从 `data/creatoros-agent-sessions` 中选取六个有真实模型 usage、请求正文快照的历史会话，覆盖选题与任务列表、计划管理、Skill 提取、Skill 文件编辑及较短混合任务。样本由工具行为人工选择，不是随机样本；数据目录可能含手工实验或测试，不能代表全部用户会话，也不能证明全为日常生产任务。记录生成于 2026-10-19 至 2026-10-30，涉及多个历史版本。会话标签描述工具行为，不声称完整表达用户意图。

执行 `python scripts/context_attribution_baseline.py`：脚本只读历史 Trace 与已记录的 ModelContext 快照，不执行历史工具、模型或业务操作。六个 session ID、目标 request ID、快照 SHA-256 和 Trace 到目标记录的前缀 SHA-256 固定在脚本中；任一缺失或不匹配时报错，而不是默默选另一份数据。Trace 后续追加不影响前缀检查。历史原始快照位于 Git 忽略的本地数据目录，未随仓库分发；其他环境没有原始数据时无法复算，不能把本文数字当作可独立重现的公开数据。输出只含工具名和数值，不复制用户正文、参数或结果。

`python -m unittest tests.test_context_attribution_baseline -v` 验证目标请求固定、记录截止、摘要输出不含正文、哈希不匹配及缺失失败。使用本地新归因函数离线分析**快照原样**，不套用当前工具投影，因此这里反映当时请求而非当前代码重新运行同任务的预测。快照由现有机制脱敏，标记 `redacted`；本次六份为 `false`，这表示没有触发已知脱敏规则，不保证不存在其他敏感信息，因而不输出正文。

## 方法

- 实际总输入及缓存命中来自目标请求的供应商 usage；累计输入只统计到目标记录之前有 usage 的已完成主请求，不含摘要请求和没有 usage 的请求。
- 逐项使用 `detailed_breakdown`，与当前 Trace 使用同一估算：基于 JSON 字符数及图片估算，不是供应商 tokenizer。各分项互斥、总和等于整包估算；逐工具结果分组是 `tool_results` 的细项，不可与总项再相加。消息包装、工具调用结构归入相应字段的口径与上一次手工分别估算字符串不同，因此数值略有差异。
- 仅依据快照当次携带的 schema 名称与 tool-call ID 配对；未知、不安全或无法唯一匹配的名称汇入 `unknown`。组内数字含工具消息自身的序列化包装。无法根据本项量化信息价值、语义质量或后续任务成功率。
- 历史快照未保存与所有当前归因参数完全等价的独立边界（例如账号文本识别），重算时账号上下文等可能归到 `recent_messages`；本次关注的推理、参数和工具结果仍按统一规则拆分。图片为估算。快照是供应商格式转换之前的请求视图，真实计量有差异。
