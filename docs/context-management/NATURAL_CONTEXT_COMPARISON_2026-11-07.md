# 自然多轮任务的上下文和缓存对照（2026-11-07）

## 方法

三类合成任务各跑旧版与新版一次，每组自然提问三轮：①选中作品后问色调和主角；②看栏目 Skill，模拟宿主把绑定从 v1 改为 v2 后再问现在及之前的 Skill；③查询栏目选题，再问目标受众和另一个选题标题。提问没有要求搜索、调用某个工具或采用某种回答格式。每轮隔 5 秒供缓存持久化，仍不能保证命中。

对照的旧版仅加载提交 `1bc0e65` 的 loop，其余模块与候选共享当前工作树依赖，不是两个完整发行版。两侧业务输入相同，system 开头各有独立随机标识以避免互相预热，标识的实际 token 数可略有差异。执行顺序分别是旧→新、新→旧、旧→新，仍有时间、随机性和服务端状态混杂。模型为真实 DeepSeek `deepseek-flash` 非思考模式，每组只跑一次；各组首次请求命中均为 0，但不能证明服务端绝对冷缓存。

选题调用使用受控内存工具替身，只允许 list/get，不访问实际 SQLite/HTTP 或正式账号；两组均调用了真实模型但没有执行真实业务操作。没有触发压缩或摘要请求，因此本对照不能评价压缩后的主动回读。每个模型请求的 usage 均按供应商返回记录；输出与实验报告仅含合成数据。

复现：`D:/Anaconda4.7g/envs/deepcode/python.exe -m tests.live_context_natural_compare --live --env-file D:/CreatorOS/.env --report tmp/<新目录>/report.json`。不加 `--live` 不调用模型；报告路径必须不存在。评分是简单检查，需复核实际回答。首次实测原版脚本按关键词判分、未内置采集回答；之后改进了脚本的回答与假工具回执记录、否定句判分，故当前脚本行为不等于本次原始运行。
