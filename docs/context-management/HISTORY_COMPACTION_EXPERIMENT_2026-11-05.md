# 历史压缩回读与检查点兼容验证（2026-11-05）

## 目的与范围

检查是否能安全地把当前接近模型窗口上限才运行的摘要提早用于日常上下文。实验使用基于选题和计划管理任务形态的**合成会话**：用户要求只制作草稿、禁止发布；一次提交回执包含 unknown、远端可能已提交；选题详情的长 brief 中间有随机暗号。数据仅存隔离临时目录，未访问正式业务库、运行生产或重放用户历史。它不是真实生产任务回放，也不评价所有后续追问。

有偿、真实 DeepSeek（`deepseek-flash`，low 思考档、无自动重试）对照：同一份合成账本分别不压缩、压缩后接受同一条追问。压缩保留完整最近轮，将较旧的完整轮次外置和摘要；压缩后主模型允许只读当前会话归档。仅执行一轮有效比较，模型输出有随机性，不能声称稳定成功率或以此估算长期费用。此脚本默认不调用模型；明确执行 `D:/Anaconda4.7g/envs/deepcode/python.exe -m tests.live_history_compaction_recall --live` 才发起付费请求。

## 对照结果

| 项目 | 原始历史 | 先压缩再追问 |
| --- | ---: | ---: |
| 追问主模型请求数 | 1 | 3 |
| 额外摘要模型请求数 | 0 | 1 |
| 原始/压缩后账本投影估算 | 6,758 | 988 |
| 摘要请求 input / output（实际） | 无 | 578 / 971 |
| 追问请求 input（实际） | 3,964 | 1,459 + 3,562 + 5,400 |
| 追问请求 output（实际） | 439 | 260 + 302 + 420 |
| 摘要 + 追问累计 input / output（实际） | 3,964 / 439 | 10,999 / 1,953 |
| 额外 read_file 调用 | 0 | 3 |

两组都回答出中间随机暗号、提交结果未知且不可重新提交、仅草稿禁止发布。压缩摘要本身**没有**暗号；主模型从本会话归档分段回读才找回它。此次压缩虽显著降低首次上下文估算，但一次追问的摘要加回读使累计输入和往返反而增加，缓存与请求数也不同；不能仅凭本例推断成本、长会话收益或将阈值提前设为某一固定值。

首次实验的未压缩对照失败：合成 `manage_topics` 返回采用了不符合实际 DTO 的顶层 `brief`，被现有模型投影过滤为空。随后按真实契约改成 `action=get`、`topic.brief` 并重跑，以上表格仅使用校正后的有效运行；不得将首次失败解释为真实工具或模型的回读缺陷。

当前实现会在生成摘要之前外置待摘要的全部工具正文；摘要只见归档说明和少数可提取的顶层事实，`[tool_error ...]` 前缀可能使 JSON 无法提取状态。本次虽然通过归档找回 unknown 与暗号，但单例不足以证明未知写入、权限、版本或之后的任意证据都能保留。因此本轮不直接下调自动摘要触发线或保留预算；应先对历史来源、普通短查询、长未完成轮、外置索引及回读失败进行更多真实任务同初始状态对照。

## 系统指令变化后的 checkpoint 校验

新增 checkpoint 同时保存原有全量 `source_digest` 与 `stable_content_independent_digest`：只将来源记录中开头连续 system/developer 消息的 `content` 字段标准化，其他字段、角色、前缀边界、所有对话与工具消息完整参与后者的摘要。原 digest 一致时沿用原逻辑；仅当前置指令文本变化且其他所有被绑定的来源内容一致，才允许新格式 checkpoint 继续使用，投影使用**当前** system/developer 内容。pin、保留后缀及新追加消息行为不变。

缺少新摘要字段的旧 checkpoint 维持原严格验证；其全量 digest 失配时无法证明只有指令发生变化，所以安全回退，不尝试猜测修复。新摘要字段格式无效时拒绝加载。摘要并不因为此改动得到质量保证或自动迁移旧记录。

定向验证通过：`python -m unittest tests.test_checkpoint_system_updates`（新指令、序列化重载、pin、追加消息、前缀角色/数量/非 content 字段变更、来源用户/工具结果篡改、旧格式与错误摘要）；`python -m tests.smoke_compaction_checkpoint`、`smoke_compacted_model_context`、`smoke_compact_session`、`smoke_context_protection`、`check_step_compaction` 通过。上述回归使用受控替身及临时数据；真实 DeepSeek 只用于前述单个有效对照。
