# 给 Judge 的八道固定考试题

这组题只问：**评分老师有没有分清自己该评什么、实际看到了什么。** 它不是给图片打审美分，也不是全项目的成功率。

| 题号 | 固定检查的问题 |
| --- | --- |
| R01 | “四格、文字清楚”和“三轮、不发布、不切栏目”混在一起时，能否分开评分项与操作限制 |
| R02 | Mind 是否只评故事、文案和情节，而不是字体、配色 |
| R03 | Visualize 是否只评呈现，不因故事立意扣分 |
| R04 | 能否保留“不加标题、不要噪点、不遮文字”这些合法的创作禁令 |
| R05 | 建标准时还没有候选，能否不假装已经收到产物或完整剧本 |
| J06 | 只有发布标题、正文时，能否承认没有完整剧本 |
| J07 | 允许补标准时，能否只补本角色的作品标准；没有图片时不假装看过 |
| J08 | 固定重评能否覆盖全部原标准，不擅自新增或放宽 |

## 怎么用

平时的零付费检查，测试的是判分器能否抓住人为构造的错误：

```powershell
python -m unittest tests.test_judge_regression_suite -v
```

需要真实检查当前 DeepSeek Judge 时，显式执行，选择一个**全新**输出目录：

```powershell
python -m tests.live_judge_regression_suite --root tmp/judge-regression-my-new-run --allow-paid
```

一次八个真实请求，复用产品的 Judge 提示词、解析器和模型设置。不调用 Codex、不生成图片、不启动服务、不写业务数据库。每题只请求一次，不自动修格式或重试；某题失败继续下一题，最后返回非零。未知请求不能被当成零用量。

每个题目目录保存：

- `request.json`：原题、预期、实际发出的完整消息、System Prompt 和摘要。
- `provider.json`：实际模型、推理程度、SDK 重试设置。
- `raw-response.json`：公开原始回复和用量，先保存再解析，不含隐藏推理。
- `result.json`：每个检查的预期、实际、是否通过；有错误另外保留 `error.json`。

根目录保存 `manifest.json`、冻结数据集副本及 `report.json`。因此失败可追到具体句子，不需要临时把全部回复读一遍才能知道哪题错了。

修正判分器后，可以对已保存的**同一批回复**离线重评，仍需全新目录：

```powershell
python -m tests.live_judge_regression_suite --regrade-from tmp/judge-regression-old-run --root tmp/judge-regression-new-score
```

这不会再次请求模型，也不写入原目录；报告将旧分数、新分数和原报告摘要分开记录。不能把离线重评分说成模型重新跑了一轮，或产品质量提高了。

## 不要误解这个分数

数据集在第一次运行前冻结，SHA256 写死在判分器中。改题或改正确答案必须另建 v2，不能覆盖 v1 或旧报告。

判分器使用这八题预先指定的短语、质量锚点、枚举和正向证据声明模式。它能抓住已覆盖的“操作伪装成内容”等错误，但不是通用语义模型；未列出的同义改写可能漏检，列出的措辞在特殊语境也可能误伤。失败应检查完整原文，分类为产品、判分器或题目表达问题，另开下一轮处理，不能就地改分。

参考材料全是题内文字；这轮不验证真实看图能力、内容审美、前端链路或 RSI 多轮收敛。八题全过只说明这一轮八个固定边界请求通过，不表示所有栏目都能生成好作品，也不保证下次随机响应一定相同。
