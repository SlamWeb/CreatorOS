本轮只减少重复资料和不必要的模型往返，不改压缩、RSI轮数、生产调度、旧任务或正式数据。新代码完成隔离验证，尚未重启正式8765。

## 从真实对话定位的原因

账号Chinese History Story，最近会话`707f5e5d-0da0-4d4b-8d87-6cfec7dd9601`；20次用户请求、52次模型请求。资料来自原始request snapshot与context-trace，仅读取，没有重写。

- 用户“这两张”替换参考图的一问实际走11次模型请求：加2图、改正文、删6图、读文件树、最终回复。9项写入全部成功。单项工具要求每次将新候选ID/digest送回模型，造成往返；不是一次API失败不断重试。
- 另一问修改字体时曾尝试编辑已被用户在Web入库的草稿，409后又读任务、文件树、全家族和正文。工具没有给出明确的生命周期转交信息，提示词又强制先列文件再读正文。
- 最近manage_topics的3次create分别批量新增3、3、10条，不是重复创建同一批。另一问4条get并行一批、4条update并行一批，属于读取CAS再修改，不应删掉必要校验。
- Skill保存、写入回执再次夹带正文；同一文件/版本重复读又重复发送正文。去掉这部分可减少每次请求大小，但不是全部上下文的大头。

最后一问的实际输入为104,593 tokens，其中缓存命中104,448，未命中145。它是单次完整上下文，不是新增10万tokens，也不是其他聊天混进这个session。历史有多次操作，不能说只进行了两三次人类请求。

同一个最后snapshot，按JSON字符粗分：assistant历史约44.3%（包括工具参数与reasoning），工具结果约35.4%，32个工具定义约14.5%，system/user约5.8%。字符比例不是token比例，不展示内部推理正文。本轮不删除assistant参数或推理；只减工具重复正文不能保证长会话永久低于10万。

## 修改

1. **模型视图和原始账本分开。** 列表/提交/保存/编辑回执只返回下一步所需身份、状态、digest、允许动作；写入参数已有全文，不再回显。显式读取保留全文、独立原始素材和凭证。author输入已原样包含在生成的Skill中时去重，普通提炼参考不删除。
2. **精确引用重复正文。** 同工具、资源、digest、文件、分页及正文完全一致时，后一次正文用`content_ref`等指向本请求内前一个唯一tool_call_id。不同版本/分页/错误结果不混用；旧读被裁出上下文后恢复全文。原始Trace、用户消息、工具参数和reasoning不变。
3. **一次取正文与目录。** `get_producer_skill(path="SKILL.md",list_files=true)`在宿主内读现有两个端点并比较digest，给模型一个结果。直接读已知根文件不再强制先列目录。
4. **既有编辑工具支持batch。** 顺序添加新图、改引用、删旧图。每项仍走已有账号/附件权限和CAS；宿主自动沿实际回执的新候选ID/digest继续。失败或未知立即停止，已完成候选保留，返回计数和失败项。不是数据库原子事务，不自动回滚或重发整批。
5. **已入库草稿正确转交。** 旧草稿编辑遇明确conflict时只读同任务核实；已saved就交付saved_skills准确ID和`edit_installed_skill`，不自动写库，不要求模型重新列全库。其他账号仍不能读取该身份。

没有增加模型工具；扩展既有读取/编辑参数并同步说明，工具集和说明在同一部署内保持稳定。没有更改选题/Run/Revision/Attempt的生产含义。
