# 评测登记契约

## 共享登记（本轮）

- `EvalRegistry` 将正式轮次、运行计划、生命周期事件和每题结果写入独立 SQLite；默认位置是用户目录下 `.creatoros/eval/registry.sqlite3`，可通过 `CREATOROS_EVAL_REGISTRY` 或构造参数指定。与业务 SQLite、工作树及历史 Benchmark 批次分离；只读查询不会创建目录或数据库。调用方必须在正式评测冻结和执行前完成登记，登记本身不会启动任何模型或外部动作。
- 轮次与运行 ID、已登记计划和已保存题目结果不可覆盖。相同内容重复提交为幂等，不同内容相同 ID 拒绝；数据使用 SQLite 写事务保证并发一致。只有计划内的题可以在运行期间写入，未收到结果的计划题保持缺失，不自动算通过或失败。
- 登记时对同轮、同套件、同题按所有先前正式申请数分配不可由调用方提供的 `round_attempt`，即使前次冻结失败也计数；同 ID 幂等登记不递增，并发事务保证唯一。已存在但缺少该字段的旧登记显示未知，不推断旧轮内首试。运行通过 `claim_execution` 原子领取：仅第一次可从 registered 进入 freezing，重复领取一律冲突，不会启动第二次外部执行。
- 运行状态为 `registered → freezing → running → completed`；非终态可转 `failed`、`interrupted` 或 `unknown`。终态不得恢复运行；重试以新运行 ID 记录，不自动重复付费任务。合并状态的变化另留追加事件。
- 对 failed/interrupted/unknown 的终态，可信本机适配器可在验证冻结 manifest 与题目 record 后显式调用 `recover_case_result`，仅追加原来未记录的计划题，并记录来源批次和 manifest/record SHA-256 及恢复事件；同内容同来源幂等、不同内容或来源冲突拒绝，不改变运行终态或执行模型。registry 核对绑定的摘要，文件内容及题目绑定由适配器负责核验。
- 正式适配器注册 `requires_manifest_binding=true`，冻结完成后、执行前只能在 freezing 状态将一次 manifest SHA-256 不可变绑定；同值幂等、异值冲突。绑定前不得进入 running；终态补录的摘要也必须与绑定值一致。旧运行不因新字段修改，未绑定的旧运行可读取但不可声称来源已认证或补录。
- 元数据与证据为限大小 JSON，拒绝常见密钥字段；生产者仍须在写入前脱敏，不在数据库保存凭证或未经授权的用户隐私。公开 HTTP 返回通过现有 `clean` 投影再次脱敏。本机共享目录的操作系统权限仍是隔离边界，不能把它视为完整身份认证。
- `/api/eval/v1/rounds` 和 `/api/eval/v1/rounds/{id}` 为只读投影；旧 `/api/eval` 与旧 Benchmark 文件读取路径保持不变。UI 只可读取登记内联的脱敏证据；其他 worktree 的文件路径不会自动映射成可读取附件。
- 运行方可显式上报心跳；处于冻结中或运行中而心跳缺失/超过 60 秒的记录，读取时显示 `display_status=unknown` 和 `liveness=unknown`，保留原始状态和事件，不代表任务已取消，也不自动重试。正在登记和终态不按心跳推断运行状态；生产者须维护心跳，未接入者会显示未知。
- 当前没有回滚执行、真实 API 鉴权和旧批迁移；题集选择和比较应以各自实现与测试为准。

## 选集与比较

- 常规/完整回归目录、资源分类和可执行资格见 [回归目录 v3](../../docs/agent-eval/regression-catalog-v3/README.md)。目录和测试集分别有冻结摘要；新增来源/题集须通过身份、血缘、分组和来源校验，新场景不因录入而自动具备执行资格。
- `regression_runner` 先生成选择计划；默认全量遇到未准入项会阻止运行，不静默跳过。显式选取已准入项并允许部分运行时，冻结目录、题目清单、守卫和改动范围，结果保留选中数与完整范围。`local-dispatch-v3` 仅用于受控隔离工作进程，保留正常工具 schema；被拒绝的危险动作及缺失追踪进入关键门禁，后台工作服务不启动；不是操作系统或网络沙箱。旧守卫与旧记录保留，执行条件不同的结果不直接比较。
- `/api/eval/v1/suites` 只读展示目录，`/api/eval/v1/suites/{id}/runs` 只展示正式登记中明确绑定该目录的运行，不跨批累加或推断覆盖。目录错误与登记读取故障分别返回错误，不伪装为空数据。
- `python -m creatoros.evaluation.change_rules tool` 等声明改动范围并生成版本化的必要/建议检查清单；当前规则是覆盖要求，不执行测试，不代表对应的回归套件均已接入。未知范围保持未覆盖；工具专项只覆盖清单中的专项本身。
- `GET /api/eval/v1/compare` 比较两次明示的正式运行；题目定义、评测框架、世界/守卫、模型、试次政策和轮内同题试次须可比。缺少条件时不计算涨跌；模型调用 Token 仅比较双方提供相同口径供应商实测的配对题，耗时和工具调用也须有相同口径。程序、语义和关键门禁仍分别记录，不给跨维度加权总分。
- 测试世界的 Web app 使用各自独立的评测登记库，浏览器回归同样设置隔离目录；不读取主机用户的共享登记。已完成的单题可在异常退出前尽力同步；进程强杀或缺完整摘要后，保留源批次但尚无自动可信补录。
