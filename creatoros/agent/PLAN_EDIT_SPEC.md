# 计划编辑职责收敛 — SPEC Draft

状态：暂缓，2026-11-01。独立复核后，用户确认先不重构：当前只一处短合并，新增编辑模式尚无明确净收益，权限检查还依赖完整合并结果。下文保留为未实施方案；重复步骤ID的独立缺陷另行窄修，不引入本方案的update_mode。

## 要解决的问题

例子：生图已经完成，Agent只提交了后续剪辑步骤的新BGM要求。程序需要保留生图历史，再检查剪辑是否还允许修改。

当前 `tools/plans.py:170–210` 先读取整个计划，合并省略步骤，并判断续接允许改什么；`agent/plans.py:336–375` 再读数据库并检查版本、已执行步骤和生产防重。工具adapter需要理解计划历史，模块的interface因此包含了过多内部知识。

目标：提高计划module的depth与locality，让Agent工具adapter逐步只表达修改意图，由计划implementation解释历史。Web与自动续接两个实际入口提供leverage；seam放在现有PlanService编辑入口，不新增执行框架。

## 第一步：只收拢“省略步骤保留”

本次拟实现范围仅为步骤合并。自动续接权限判断、已提交不可改、账号校验、未知结果不重提继续生效。

| 调用方式 | 省略一个步骤是什么意思 | 顺序 |
| --- | --- | --- |
| 现有Web/普通编辑 | 沿用完整列表替换语义；删除仍受已执行保护 | 沿用提交顺序 |
| 自动续接的局部编辑 | 未提及的步骤保持原定义、结果和错误，不当成删除 | 原步骤顺序保留，新步骤按提交顺序追加 |

合并在PlanService同一次写事务中，基于最新的已存步骤完成；先校验账号、当前契约、expected_version，再合并、验证、写入。任一检查失败，整次编辑不落库。

### 调用链及契约

```text
Agent manage_plan(update)
  → 工具从RuntimeContext决定编辑方式
  → 现有计划PATCH
  → PlanService：版本检查 → 合并 → 既有业务检查 → 保存
```

- 沿用 `manage_plan`，模型参数不新增编辑方式、账号或自动续接身份。
- 内部PATCH增加显式 `update_mode: replace | merge`，默认replace，保持现有网页调用含义。工具依据宿主context在自动续接时传merge。
- update_mode只决定省略项语义，不授予权限；两种模式均经过原会话归属、版本、契约、已执行保护和生产防重。
- 自动续接仍绑定原plan_id。普通用户不能通过模型参数自称自动续接。
- 合并后的步骤再做完整结构/依赖/工具参数验证；未知ID为新增步骤，重复ID拒绝。保留原步骤结果、错误及修复历史。
- 返回沿用现有计划结果：实际version、步骤和真实状态；不加模型需要理解的新状态，不改变ToolResult投影。

## 保持的行为

- 已开始/成功/失败/未知的步骤不能被局部编辑覆盖或删除；既有可证明提交前失败的修复例外沿用原规则。
- 生产仍运行、失败或结果未知时，不靠新增替代步骤重新提交。旧图片和运行记录不改。
- 已经计划好的、未开始的视频可以在现有规则允许范围调整inputs；本步不新增其他生产修改权限。
- expected_version冲突先返回409；账号/会话不符拒绝。旧契约计划只读，不迁移或自动恢复。
- 暂停/恢复/重试/跳过、生产队列、Codex、Skill版本、审批发布、SQLite表结构保持原逻辑。

## 小范围验收

1. 局部编辑一个待执行步骤，省略的成功/失败步骤定义、错误、结果逐字段不变。
2. 新步骤按序追加，重复ID、坏依赖、非法工具参数整次拒绝。
3. Web默认replace语义保持；删除已执行步骤仍拒绝。
4. 版本冲突、跨会话修改均无写入；运行/未知生产不能被换名重提。
5. 工具→真实本机HTTP→PlanService验证merge，确认工具不再自行补全遗漏步骤。
6. 一条隔离原前端+真实DeepSeek的检查点续接：只改一个待执行的只读步骤，历史保留并继续完成。记录真实修改参数与数据库前后状态。

本地数据变换/故障注入可受控；HTTP及SQLite走真实实现。此改动不需要生成图片，已有生产防重回归复用本地工件，付费模型验证另列。无需重跑50题，也不修改旧评测分数。

## 第二步的进入条件

第一步通过后，再讨论把自动续接的完整修改策略移进计划module。当前StudioClient只传会话身份，没有自动续接plan身份的受信传递；在来源尚未由宿主可靠绑定前，不能仅加一个客户端 `is_automatic` 开关就删除工具侧限制。

第二步另列方案和权限矩阵，证明Web、用户Agent、自动续接三个入口的原权限都被覆盖后，才删除重复决策。若interface没有减少调用者需要知道的历史规则，则停止扩大重构。
