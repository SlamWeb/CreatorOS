- User authorized a lighter default: check running/authorized queued work, close admission, back up SQLite, gracefully restart and verify the new instance/health before opening consumers. Do not scan/hash historical files or dump/compare all business rows during routine restart.
- Keep full preservation checks for pending schema migrations (automatically selected) or explicit `restart --full` for recovery work. Full mode takes one snapshot and compares it once after startup; remove the redundant pre-stop full comparison. No new task recovery, RSI replay, production, deletion or data rollback.
- Preserve existing busy/admission/instance handoff protections, rather than adding more defensive layers. Verify both modes, automatic migration selection and running/queued refusal against temporary SQLite/files and real isolated HTTP/processes; formal service must not be restarted this turn.
- Implementation: `restart` defaults to `verification=startup`, with no full-row dump or historical file hashing. Pending Alembic upgrades automatically use `full`; explicit `--full` supports recovery verification. Full mode compares the pre-restart snapshot once after startup. Startup-only reports do not claim file/row equality that was not checked. This supersedes the older always-full default below.

## Draft · 2026-10-23

- User authorized a reusable safe-maintenance command and frozen Judge regression tests. This module replaces untracked, date-specific restart snippets; it does not run maintenance against formal data during development.
- `python -m creatoros.maintenance check` is read-only: configured SQLite, actual queue authorizations, auxiliary metadata, execution journal and (when managed) live instance activity. Busy, malformed, unknown, linked or unavailable evidence blocks restart. A queued Run without execution authorization is not automatically produced.
- `restart` owns a separate local orchestration lock and controls only a registered Studio instance through a random local token and instance identity. No PID killing, OS-wide process scanning, automatic adoption of legacy servers, data deletion or automatic restore. Legacy services without the protocol require one explicit manual stop/start.
- The running host must check busy activity before maintenance admission closes, so accepted chat tools are not interrupted. Once idle, new API mutations are rejected and new automatic feedback jobs are paused; the authorized controller can backup and request graceful exit. A newly launched replacement starts with consumers deferred, so no queued/model/feedback work can run before old-data verification.
- SQLite backup is exclusive; compare original tables/columns/row values, not physical database bytes. Compare all historical managed Skill/production/research/chat/discussion files by SHA256. Integrity and foreign keys must pass. Existing RSI config/state, standards, scores, images and model receipts are not rewritten or re-evaluated.
- Authentication requires loopback, no Origin, exact random token and instance identity. Tokens are local ignored runtime state, never command-line arguments, URLs, public health output or tracked logs. Concurrent/mismatched/unknown requests fail closed.
- Verification uses temporary SQLite/directories, controlled fault injection and real isolated HTTP/process restart, with no paid production or formal service mutation. Tests cover busy channels, paused RSI with live/unknown trial, corrupt metadata, no hidden replay, deferred startup, admission races, authentication and full-row/file preservation.

## Implementation and audit · 2026-10-23

- Implemented `check|restart`, authenticated local admission, exclusive host/orchestration locks, pre-migration legacy execution lock, deferred consumers and SQLite/row/file verification. Default Studio consumer behavior is unchanged. No OS termination, old-RSI replay, new production or formal restart was performed.
- File hashes also include TopicReferenceStore originals/frozen bundles. Paused RSI checks nested trial/model receipts; valid historical research `stale` remains terminal. Migration bookkeeping is separate: only unchanged revisions or repository heads are allowed; old business values still must match.
- Windows Python 3.10 reparse attributes protect all path ancestors. Receipt uses random exclusive temporary creation/atomic replacement; custom maintenance directories are Git-ignored. These are local accidental-operation safeguards, not Windows ACL isolation against the same user.
- Independent audit found and fixed junction handling, Git ignore, reference coverage, stale state, migration version handling, malformed receipts and double-failure diagnostics. Disk-full logs cannot skip restoring admission before stop; handoff waits for old process completion so Windows handles close.
- Development failures: SQLite context managers did not close handles; the first process test reached port/lock release before interpreter log handles closed. Explicit closure and process completion checks fixed both; isolated process rerun 2/2 passed. Fault injection is not real production/model success data.
